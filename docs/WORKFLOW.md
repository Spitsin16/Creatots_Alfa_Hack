# Совместная разработка

1. Перед работой прочитать нужный раздел `docs/TZ.md` и проверить открытые pull request по своей области.
2. Работать в отдельной ветке; если меняется чужая область, согласовать файлы до правки. Не перезаписывать чужую незакоммиченную работу.
3. В описании pull request кратко указать сделанное, способ проверки, известные ограничения и следующий шаг.
4. Перед PR выполнить из `backend/`: `ruff check .` и `python -m pytest -q`. Изменение `data/rules.yaml` требует сверки всех персон с `data/reference/expected.json` и осознанного обновления эталона в том же PR.
5. Вливать в `main` только PR с зелёными проверками `backend`, `Frozen reference data`, `frontend` и `docker compose up from scratch`. Защита `main` включена: обязательный PR, повторное ревью после новых коммитов, актуальность ветки и запрет обхода правил.

Workflow CI запускается на каждый push любой ветки и на каждый PR.
