# Совместная разработка

1. Перед работой прочитать `docs/PROGRESS.md`, затем нужный раздел `docs/TZ.md`. Проверить, кто владеет областью в `AGENTS.md`.
2. Работать в отдельной ветке; если меняется чужая область, согласовать файлы до правки. Не перезаписывать чужую незакоммиченную работу.
3. Перед завершением смены обновить верхнюю запись `docs/PROGRESS.md`: дата и исполнитель, сделанное, ветка и текущий файл, что сломано, следующий конкретный шаг. Добавить эту запись в тот же коммит, что и код, **до коммита**.
4. Перед PR выполнить из `backend/`: `ruff check .` и `python -m pytest -q`. Изменение `data/rules.yaml` требует сверки всех персон с `data/reference/expected.json` и осознанного обновления эталона в том же PR.
5. Вливать в `main` только PR с зелёными проверками `backend` и `reference`. Для этого после подключения GitHub включить защиту ветки `main`: обязательный PR, обязательные status checks `backend` и `reference`, запрет обхода правил. Пока удалённый репозиторий не подключён, GitHub не может применять эту защиту.

Workflow CI запускается на каждый push любой ветки и на каждый PR. Проверка `frontend` автоматически включится после появления `frontend/package-lock.json`.
