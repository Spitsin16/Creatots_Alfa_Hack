# Допущения

Что мы приняли без подтверждения банка и почему. Каждое допущение можно поменять, не трогая архитектуру.

## Объём и клиенты

| Допущение | Почему | Где поменять |
| --- | --- | --- |
| Кабинет — только для действующих клиентов Альфы (ИП и ООО со счётом) | Подтверждено организаторами (Q&A 3, 9). Данные о бизнесе уже в банке — анкета без выручки, отрасли, адреса | ТЗ 1.1 |
| Вход тестовым логином вместо Альфа-Бизнеса | В демо нет боевой авторизации | `api/routes.py` `/auth/login` |
| Согласие на БКИ и ФНС — одна галочка, действует год | Минимум трения; реальный срок определяет юрист банка | `routes.py` `create_consents` |
| Подпись договора — демо-код `0000` вместо ПЭП/Госуслуг | Нельзя подключать реальные сервисы | `DEMO_SIGN_CODE` |
| Выдача симулируется воркером сразу после подписи | Нет АБС | `worker.py` `CONTRACT_SIGNED` |

## Данные

| Допущение | Почему |
| --- | --- |
| Все персоны, обороты, выписки и банки синтетические; ИНН банка в выписке — `7700000001`, название «АО «Банк Пример» (синтетический)» | Запрет на реальные персональные данные |
| «Сегодня» = `DEMO_TODAY=2026-10-22` | Детерминированные расчёты и прогноз |
| Внешние системы (Альфа, ЕГРЮЛ/ЕГРИП, ФНС, БКИ, МЧД) — сервис `mocks` по ИНН | Реальные интеграции запрещены; замена мока на интеграцию не меняет конвейер |
| Выручка в Альфе — входящие с типом `REVENUE`; свои переводы, кредиты, возвраты не выручка | Так банк считает «чистый» оборот |
| В выписке 1С выручка — входящие от чужих ИНН, без слов «собственных», «кредит», «займ», «возврат», «процент», «депозит», «субсидия», «овердрафт» в назначении; неполный первый месяц не берём | Простое и проверяемое правило; спорные операции видит андеррайтер |
| Выписка нужна минимум за 3 полных месяца | Меньше — нет базы для средней |

## Правила решения

| Допущение | Почему |
| --- | --- |
| Ключевая ставка 14%, минимальная ставка — ключевая + 1 п.п. | Реалистичные ставки (Q&A); значение в `rules.yaml` |
| Платёж по всем кредитам ≤ 25% выручки | Консервативная оценка для МСБ без отчётности |
| Коэффициенты LTV залога 0,6 / 0,5 / 0,4 и −2 п.п. за залог | Условные, ждут подтверждения эксперта |
| Сумма > 5 млн — второе одобрение риск-менеджера | Принцип четырёх глаз для крупных сумм |
| Веса факторов и границы классов подобраны так, чтобы 7 персон давали разные исходы | Демонстрация всех веток; `p2b` и `p_stop` ровно на границе класса D (45) |

## Сроки и связь

| Допущение | Почему |
| --- | --- |
| Ручная проверка — до 1 рабочего дня; ответ в чате — 4 рабочих часа, 9:00–18:00 МСК, пн–пт, праздники не учитываем | Собственный SLA (Q&A 42 — плюс); календарь праздников — следующий шаг |
| Звонков нет; SMS — заглушка: запись `SMS_STUB` в журнал аудита | Основной сценарий — внутри продукта, платные шлюзы запрещены |
| Уведомления в кабинете обновляются опросом раз в 5 секунд | Проще WebSocket, достаточно для демо |

## Отказоустойчивость

| Допущение | Почему |
| --- | --- |
| Внешний источник: 3 повтора с паузой 0,5 / 1 / 2 с, таймаут 5 с; потом заявка уходит специалисту с пометкой «источник недоступен» | Заявка не теряется и не зависает |
| 404 от источника («не найден») не повторяем | Это ответ, а не сбой |

## LLM

| Допущение | Почему |
| --- | --- |
| Основной режим — шаблоны без LLM | У проверяющих нет GPU (Q&A 41, 56) |
| LLM — любой OpenAI-совместимый API (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`), по умолчанию Ollama + Qwen2.5-7B-Instruct | Открытые веса, скачиваются при первом запуске (Q&A 20, 57) |
| LLM только переформулирует готовые факты; числа сверяются с входом, иначе шаблон | Решение принимают правила, а не модель |
