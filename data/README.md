# Данные для бэка: правила, тестовые персоны, эталон

Версия 22.10.2026. Все данные синтетические. Названия банков и компаний вымышлены.

## Что внутри

| Файл | Что это | Кому |
| --- | --- | --- |
| `rules.yaml` | Правила решения rules_v1: стоп-факторы, скоринг, классы, продукты, лимит, ставка, залог, исходы, советы «как получить больше» | бэк: грузит при старте в таблицу `rules` |
| `personas/p*.json` | 7 тестовых клиентов. В каждом блоки `alfa` (человек, счёт, кредиты Альфы, ~550–770 операций за год), `registry`, `fns`, `bki`, и `persona` (логин, сценарий анкеты, ожидаемый исход) | бэк: фикстуры сервиса `mocks` и сид БД |
| `personas/bank_users.json` | Сотрудники банка: `uw1`, `uw2`, `risk1`, `admin1` (пароль `demo`) | бэк: сид пользователей |
| `statements/p3b_other_bank_1c.txt` | Выписка p3b из другого банка в формате 1С (windows-1251, CRLF) | фронт: загрузка в демо; бэк: тест парсера |
| `reference/engine.py` | Эталонная реализация `rules.yaml` на Python — «оракул» для тестов | бэк: сверять свой сервис |
| `reference/expected.json` | Что должен выдать бэк по каждой персоне: класс, баллы по факторам, продукт, лимит, ставка, исход, советы, прогноз разрыва | бэк: pytest |
| `reference/generate_personas.py`, `make_statement.py` | Генераторы данных (детерминированные) | если нужно поменять персону |

Пересобрать всё: `python reference/generate_personas.py personas && python reference/make_statement.py personas/p3b.json statements/p3b_other_bank_1c.txt && python reference/engine.py rules.yaml personas --json reference/expected.json`

## Как бэку это использовать

1. **Моки.** Сервис `mocks` отдаёт по ИНН: `/alfa/{inn}` → блок `alfa`, `/registry/{inn}` → `registry`, `/fns/{inn}` → `fns`, `/bki/{inn}` → `bki`, `/mchd/{inn}` → `persona.employees[].mchd`. Ошибки для демо отказоустойчивости: `?fail=timeout|500`.
2. **Сид БД.** Пользователи из `persona.login` / `persona.employees` / `bank_users.json`, бизнесы из `registry`, правила из `rules.yaml` как версия 1.
3. **Тесты.** Для каждой персоны вызвать расчёт с `persona.scenario` и сравнить с `expected.json`: `cls`, `score`, `factors`, `product`, `limit`, `rate`, `outcome`, коды советов. Допуск по деньгам — ±10 000 ₽ (округление лимита).
4. **Выручка.** Месяцы — только полные и после открытия счёта (у p3b — 7 месяцев: март–сентябрь 2026). Выручка = входящие `kind: REVENUE`. `OWN_TRANSFER` с «р/с в» в назначении — переводы из другого банка: не выручка, но сигнал для доли оборота и совета «загрузите выписку».
5. **Прогноз разрыва** (`reference/engine.py`, функция `cashflow_forecast`): регулярные списания = один получатель, ≥3 раза за 120 дней, день месяца ±3, сумма ±15%; плюс квартальный налог 28-го; поступления — среднее по дню недели за 90 дней; нерегулярные расходы — среднее в день. Вывод владельцем прибыли (`OWNER_WITHDRAWAL`) в прогноз не включаем.

## Что ещё не решено (спросить эксперта / на созвоне)

- Дисконты к залогу (`collateral.ltv`) — условные, уточнить у эксперта.
- p2b и p_stop стоят ровно на границе класса D (45 баллов): при правке весов они могут сменить исход — после изменений правил всегда прогоняйте `engine.py`.
