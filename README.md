# Умный кредитный кабинет предпринимателя

Разработка MVP для хакатона. Требования и принятые решения: [docs/TZ.md](docs/TZ.md). Текущая передача смены: [docs/PROGRESS.md](docs/PROGRESS.md).

## Что уже запускается

- Детерминированный расчёт предложения из `data/rules.yaml` для семи синтетических персон.
- FastAPI с тестовым входом, профилем `/api/v1/me`, предрасчётом, заявкой, трекером, подписанием и симулированной выдачей; Swagger на `/docs`.
- API кабинета банка: очередь, карточка с внутренними факторами, назначение андеррайтера, ручное решение, контроль риск-менеджера и журнал аудита.
- React-интерфейс для клиента и сотрудника банка: тестовый вход, предложение, черновик и отправка заявки, трекер, очередь и карточка банка.
- Единый граф разрешённых переходов статусов и outbox-воркер автоматического решения.
- Схема из 17 таблиц, миграция Alembic и повторяемая загрузка синтетических пользователей, бизнесов, снимков данных и `rules_v1`.
- CI при каждом push и PR: Ruff, pytest, миграция на PostgreSQL 16, сверка расчёта с `expected.json` и сборка фронта.

Администрирование правил и внешние моки ещё в разработке. Статус задач записан в `docs/PROGRESS.md`.

## Запуск одной командой (Docker)

Нужны Docker и Docker Compose v2. Из корня проекта:

```bash
docker compose up --build
```

Первая сборка занимает несколько минут. Потом:

| Что | Адрес |
| --- | --- |
| Кабинет клиента и банка | http://localhost:8080 (банк — `/bank`) |
| API и Swagger | http://localhost:8000/docs |
| Моки внешних систем, переключатель сбоев | http://localhost:8100/docs |

Логины (пароль везде `demo`, код подписи `0000`): клиенты `p1a`, `p1b`, `p2a`, `p2b`, `p3a`, `p3a_acc` (бухгалтер по МЧД), `p3b`, `p_stop`; банк `uw1`, `uw2` (андеррайтеры), `risk1` (риск-менеджер), `admin1` (правила). Главный сценарий — `p3b`.

При старте API сам применяет миграции и загружает синтетические данные; повторный запуск данные не дублирует. Сбросить всё: `docker compose down -v`.

LLM необязательна, без неё объяснения строятся по шаблонам. Включить локальную модель (~5 ГБ, скачивается при первом запуске): `LLM_BASE_URL=http://ollama:11434/v1 LLM_MODEL=qwen2.5:7b-instruct-q4_K_M docker compose --profile llm up --build`.

## Нагрузочный прогон

Скрипт без внешних зависимостей: каждый виртуальный пользователь проходит вход → профиль → предрасчёт → объяснение → прогноз.

```bash
python tools/loadtest.py --base http://localhost:8080 --users 20 --seconds 60
```

Первый замер (22.10, 10 пользователей, 20 с; uvicorn в один процесс на SQLite, без Docker — нижняя граница):

| Запрос | p50, мс | p95, мс | Ошибки |
| --- | --- | --- | --- |
| вход | 511 | 1025 | 0 |
| профиль | 222 | 347 | 0 |
| предрасчёт | 472 | 844 | 0 |
| объяснение | 378 | 590 | 0 |
| прогноз | 301 | 494 | 0 |

Итого 23,8 запроса в секунду, 0% ошибок. Вход дольше остальных из-за намеренно медленного хеширования пароля. Замер на `docker compose` с PostgreSQL заменит эту таблицу.

## Запуск без Docker (для разработки)

Нужен Python 3.12. Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.lock
cd backend
ruff check .
python -m pytest -q
export DATABASE_URL=sqlite:///./credit-dev.db
export JWT_SECRET=local-demo-secret
export DEMO_SIGN_CODE=0000
alembic upgrade head
python -m app.seed
uvicorn app.main:app --reload
```

В другом терминале из `backend/` запустите обработчик заявок:

```bash
source ../.venv/bin/activate
export DATABASE_URL=sqlite:///./credit-dev.db
python -m app.worker
```

После запуска API: `http://127.0.0.1:8000/docs`. Для главного демо-сценария используйте логин `p3b`, пароль `demo`, код подписи `0000`. Банк: `uw1`/`uw2` — андеррайтеры, `risk1` — риск-менеджер; пароль `demo`.

Интерфейс запускается отдельно:

```bash
cd frontend
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`; запросы `/api` Vite направляет в локальный backend на порту 8000.

SQLite здесь удобна только для локальной проверки. Основная БД по ТЗ — PostgreSQL 16; адрес для неё показан в `.env.example`.

Все данные в `data/` синтетические. Финансовые правила и ставки являются демонстрационными.
